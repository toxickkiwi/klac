# Парсер вакансий для канала «Клацай, працуй!» — бриф

Статус: бриф согласован по основным пунктам, осталось несколько уточнений (раздел 9).
Канал: https://t.me/klacprac

## 1. Задача

Каждый день находить **2 новые вакансии в Минске** по маркетингу и смежным сферам и присылать их в Telegram **уже оформленными как пост канала**, чтобы оставалось только проверить и опубликовать.

## 2. Ограничения

- Владелица канала запускает и поддерживает парсер сама, опыта в программировании мало → всё должно настраиваться без кода: через веб-интерфейс GitHub и один файл настроек.
- Бюджет — 0 ₽: никаких платных серверов, прокси и платных API.
- Срок — как можно скорее → сначала минимальная рабочая версия, улучшения потом.

## 5. Формат поста

Шаблон по примеру из канала:

```
{Должность} / {Компания} 🌸

⚡️ {Зарплата или «Договорная»}
⚡️ {Офис / Удалёнка / Гибрид} / Минск, {адрес, если есть}
⚡️ {Опыт работы …}

⏺️ ОБЯЗАННОСТИ:
— …   (не больше ~9 пунктов; если пунктов больше — «...и так далее! (подробнее на сайте)»)

⏺️ КОГО ИЩУТ:
— …

⏺️ УСЛОВИЯ, КОТОРЫЕ ПРЕДЛАГАЮТ:
— …

💌 ОТКЛИКНУТЬСЯ:
по ссылке ({url})!

#{формат} #{опыт} #{сфера}

📌 Еще больше вакансий — ищите в канале Клацай, працуй! (https://t.me/klacprac)
```

Хэштеги:
- формат: `#офис`, `#удаленка`, `#гибрид`;
- опыт: `#безопыта`, `#до1года`, `#от1годадо3лет`, `#от3до6лет`, `#от6лет`. Нужно сверить с теми, что уже используются в канале;
- сфера: из таблицы в разделе 3.

Если у вакансии нет чётких блоков «Обязанности / Требования / Условия» (так бывает на агрегаторах), пункты выделяются по маркерам списка. Если и это не получается, ставится короткая выжимка, а пост помечается «⚠️ проверь оформление».

## 6. Как это работает

```
GitHub Actions (бесплатно, по расписанию раз в день)
   └─ Python-скрипт
        1. Обходит источники (этап MVP: rabota.by + praca.by) по ключевым словам
        2. Фильтрует: Минск, тематика, стоп-слова, не публиковалось раньше
        3. Выбирает 2 лучшие вакансии
        4. Скачивает их полные страницы и собирает пост по шаблону
        5. Отправляет 2 сообщения через Telegram-бота
        6. Запоминает отправленное в файле sent.json (хранится в репозитории)
```

- **Куда отправлять.** По умолчанию бот пишет в личный чат владелице: она проверяет текст и пересылает или публикует его в канал. Позже можно переключить одной настройкой, чтобы бот публиковал прямо в канал или ставил отложенный пост.
- **Бесплатно.** Публичный репозиторий использует GitHub Actions без ограничений. У приватного есть 2000 минут в месяц, а один запуск занимает около минуты.
- **Настройки.** Файл `config.yaml` с ключевыми словами, стоп-словами, временем запуска и числом вакансий в день. Его можно редактировать прямо на github.com.
- **Секреты.** Токен бота и ID чата хранятся в GitHub Secrets, в коде их нет.
- **Риск.** Серверы GitHub находятся за пределами Беларуси, и часть белорусских сайтов может их блокировать. Если так случится, есть два бесплатных выхода: запускать скрипт на своём компьютере через планировщик задач Windows/macOS или выбрать источники, которые не блокируют.
- **Оповещение о поломке.** Если за день не нашлось ни одной вакансии или сайт поменял вёрстку, бот пришлёт сообщение «⚠️ не удалось собрать вакансии с …», чтобы поломка не прошла незамеченной.

### Стек
Python 3.12, `httpx`, `selectolax`, отправка через Telegram Bot API напрямую (без фреймворков), GitHub Actions.

### Возможное улучшение (этап 3)
Переписывать «Условия» живым языком, как в примере («Стабильность. …», «Развитие. …»), через бесплатный тариф LLM. В MVP этого нет: текст берётся из вакансии как есть, а живые формулировки владелица дописывает вручную, если захочет.

## 7. Что нужно сделать владелице (с пошаговой инструкцией)

1. Создать бота у @BotFather и получить токен (~2 минуты).
2. Написать боту `/start` и узнать свой chat ID (инструкция будет в README).
3. Добавить токен и chat ID в Secrets репозитория на GitHub.
4. Нажать «Run workflow», чтобы проверить работу.

## 9. Открытые вопросы

1. Бот присылает посты **вам в личку на проверку**, или сразу публикует в канал? (Рекомендация: начать с лички.)
2. В какое время присылать вакансии? Нужны ли они по выходным?
3. Какие хэштеги опыта и формата уже используются в канале? Пришлите 2–3 поста с другими вариантами, например без опыта или с удалёнкой.
4. Подходят ли вакансии с удалёнкой от минских компаний? А из Минского района?
5. Что точно не публикуем: продажи, стажировки, неоплачиваемые вакансии, вакансии без описания?
6. Есть ли у вас аккаунт на GitHub? Если нет, его нужно создать, это бесплатно.
